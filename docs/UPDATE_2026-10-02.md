# 2026-10-02 — 작업 복구와 숫자 테이블 수정

이전 작업 폴더가 없는 환경에서 일본판 원본과 보관된 한국어 패치 ISO를 비교해 작업을 복구했다.
보관된 ISO는 공개 v19와 다른 파일이므로 그 파일의 기존 변경을 보존했다.

## 확인된 변경

- 한글 `찢`의 이동 인덱스 12000을 호스트 역변환에서 지원한다. 슬롯 도구와 EBOOT 빌드 도구가 같은 검증 함수를 사용한다.
- 원문 위치·바이트·슬롯 용량·NUL 패딩·코덱 왕복을 확인해 번역 3,920슬롯을 복원했다.
  미션 271개는 원본의 메타데이터와 자기 포인터로 전체 3줄 경계를 확인했다. 복구 CSV는 미승인 초안이며 로컬에만 보관한다.
- 원래 2바이트 폭으로 읽히는 숫자 테이블이 ASCII 배열로 바뀐 회귀를 복구했다.
  런타임 숫자 0~9의 PGF 코드 463~472는 같은 폰트의 ASCII 숫자 글리프에 연결했다.
- 제공 ISO에서 EBOOT 20바이트와 폰트 맵 17바이트, 합계 37바이트만 변경했다.
  폰트 글리프 기록·메트릭·158,464바이트 크기와 다른 모든 ISO 바이트는 보존했다.

차분 패치와 게임 데이터는 이번 코드 갱신에 포함하지 않는다. 현재 공개 개발 릴리스는 `dev-2026-09-26`이다.

## 숫자 수정 빌드 재현

README의 Python/hanpatch 환경을 준비하고, 위 두 ISO를 프로젝트 루트에 직접 제공한다.
아래 명령에서 원본 파일 이름은 `original_japanese.iso`, 보관된 패치는 `provided_patch.iso`로 표기했다.
파일 이름보다 위 해시가 일치해야 한다. 원본만으로 보관된 패치의 내용을 복원할 수는 없다.
`pyeboot`는 원본 EBOOT 복호화에 사용하는 선택적 의존성이다.

```powershell
.\.venv\Scripts\python.exe -m pip install pyeboot==0.2.3
.\.venv\Scripts\python.exe tools\extract_iso.py original_japanese.iso analysis\original /PSP_GAME/SYSDIR/EBOOT.BIN
.\.venv\Scripts\python.exe tools\extract_iso.py provided_patch.iso analysis\provided /PSP_GAME/SYSDIR/EBOOT.BIN /PSP_GAME/SYSDIR/UPDATE/DATA.BIN
.\.venv\Scripts\python.exe -c "import pyeboot; pyeboot.decrypt(r'analysis\original\PSP_GAME\SYSDIR\EBOOT.BIN', r'analysis\original_decrypted_eboot.elf')"
.\.venv\Scripts\python.exe tools\repair_fixed_width_digits.py analysis\original_decrypted_eboot.elf analysis\provided\PSP_GAME\SYSDIR\EBOOT.BIN analysis\provided\PSP_GAME\SYSDIR\UPDATE\DATA.BIN build\digit_repair
.\.venv\Scripts\python.exe tools\build_digit_repair_iso.py provided_patch.iso build\digit_repair build\digit_repair\next_plus_digit_repair.iso
```

수정 도구는 확인된 원본/보관 패치의 ELF·폰트 해시만 받아들이고, 빌드 도구는 보관된 패치 ISO의 해시를 검사한다.
다른 파일이거나 기존 출력이 있으면 중단한다. ISO 메타데이터·크기·다른 데이터의 보존과 삽입 파일의 읽기 결과를 검증한다.
빌드 후에는 ISO 옆 `.manifest.json`에서 전체 해시와 37바이트 변경을 확인한다.
폴더 재사용으로 기존 출력을 덮어쓰지 않고 새 출력 경로를 지정한다.

## 원문 연결 워크북 복구

`recover_source_workbook.py`는 복호화한 일본판 원본 ELF, 검증된 공개 v19 ELF, 보관 패치 ELF,
원본 인벤토리와 한국어 공개 초안을 입력받는다. 공개 v19는 기존 개발 릴리스의 xdelta를 일본판 원본에 적용해 재구성한다.
미션 자료는 `parse_next_plus_mission_records.py`로 원본에서 재추출한다.
2026-10-02 문장 검수 이후에는 아래의 **수정 전 고정 초안**을 입력한다.
복구 도구가 기존 패치에 삽입된 표현을 대조하므로, 현재 번역 파일을 쓰면 바뀐 문장의 복구가 누락될 수 있다.

```powershell
.\.venv\Scripts\python.exe tools\inventory_eboot_text.py analysis\original_decrypted_eboot.elf analysis\eboot_inventory
.\.venv\Scripts\python.exe tools\parse_next_plus_mission_records.py
.\.venv\Scripts\python.exe tools\recover_source_workbook.py analysis\original_decrypted_eboot.elf analysis\v19.elf analysis\provided\PSP_GAME\SYSDIR\EBOOT.BIN analysis\eboot_inventory\eboot_text_inventory.json translations\baselines\development_draft_2026-09-26_ko_only_pre_polish.jsonl work\recovered --mission-records work\next_plus_mission_handoff_v2\structural_records.jsonl
.\.venv\Scripts\python.exe tools\apply_workbook_slots.py build\digit_repair\digit_fixed.elf work\recovered\recovered_translations.csv --check-only --report analysis\recovered_slot_readback.json
.\.venv\Scripts\python.exe tools\audit_workbook_font.py work\recovered\recovered_translations.csv build\digit_repair\digit_fixed.pgf analysis\provided\PSP_GAME\SYSDIR\UPDATE\DATA.BIN analysis\recovered_font_audit.json
```

`analysis/v19.elf`는 재구성한 v19 ISO의 `/PSP_GAME/SYSDIR/EBOOT.BIN`을 `extract_iso.py`로 추출해 준비한다.
복구 시 검사 ID만으로 원문을 연결하지 않고 원본 주소·바이트·구조를 확인한다.
313후보는 용량·별칭·출처 등의 이유로 보류했으며 모두 게임 결함을 뜻하지 않는다.
고정 초안의 해시와 줄 끝 형식은 [baselines/README.md](../translations/baselines/README.md)에 기록했다.

## 검증과 수용 범위

코덱 회귀 테스트 7개와 `pip check`가 통과했다. 복구 슬롯 3,920개는 수정 ELF에서 읽기 확인됐고,
필요한 폰트 코드 961개와 런타임 숫자/상표 코드도 존재한다. 이전 숫자 수정 ISO와 차분 재적용 결과는 같은 해시다.
사용자는 이번 작업을 확인하고 수용했으며 추가 CMD 실행 검증은 필요하지 않다고 명시했다.
이 수용은 이번 변경 범위에 대한 것이며 전체 번역 초안 승인이나 새 실기·장면별 캡처 검증을 뜻하지 않는다.
추가 CMD 요청은 종료됐다. 남은 기술 조사와 다음 작업 기준은 [HANDOFF_CURRENT.md](HANDOFF_CURRENT.md)에 기록했다.
