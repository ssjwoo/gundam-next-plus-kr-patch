# 020 첫 로딩 정지 — 021 수정 및 사용자 부팅 확인

사용자는 `next_plus_graphics_revision_020.iso`가 PSP-3000과 PPSSPP에서 PSP 로고 직후 NOW LOADING 화면을 벗어나지 못한다고 보고했다. 020의 정적 검사 PASS는 유지하되, 실행 상태를 사용자 보고 FAIL로 기록한다. 검사값을 고친 021에 대해 2026-10-03 사용자가 부팅 완료와 현재까지의 정상 게임플레이를 보고했다. 첫 로딩 문제는 `CLOSED_USER_REPORTED_PASS`로 기록한다. 이번 재시험의 기기별 결과·플레이 범위는 별도로 주어지지 않았으며 전체 모드 검증으로 확대하지 않는다.

PZZ 파일의 마지막 16바이트를 의미 미확정 상태에서 원본 그대로 보존한 것이 발견된 결함이다. 게임의 `0x08885A84` 로더는 이 16바이트를 복사해 비동기 처리 `0x08887910`에 넘긴다. 처리 함수 `0x088879E0`은 `0x088BD520`을 호출하고, 이 함수는 `0x088BD728`이 해제와 함께 계산한 16바이트를 원본 값과 비교한다. 수정된 466멤버의 원본은 모두 통과했지만 020의 값은 모두 실패했다.

검사 함수는 파일 끝 16바이트를 제외한 본문 길이로 XOR 키를 정한다. 해제된 본문의 32비트 무부호 워드를 순서대로 64비트 합에 더하고, 각 누적합을 다른 64비트 값에 XOR한다. 합의 초기값은 `((본문 바이트 수 * 7) & 0xffffffff) >> 1`이며, XOR 초기값은 모든 비트가 1이다. 끝의 검사값은 본문의 XOR 암호화와 별도로 직접 저장된다. 일반적인 MD5·CRC 검사가 아니다.

`tools/pzz_integrity.py`가 관찰한 워드 정렬 형식의 검사값을 계산한다. 패커는 입력과 출력 검사값을 확인하고 변경한 본문의 값을 다시 기록한다. ISO 빌더도 잘못된 검사값의 입력을 거부한다. 의미를 모르는 값을 임의로 보존하거나 0으로 채우는 방식으로 통과시키지 않는다.

021은 020 각 멤버의 마지막 16바이트만 고친다. 466멤버의 본문·압축 스트림·해제 결과는 020과 동일하다. 원본 EBOOT의 검사 함수만 격리된 MIPS CPU에서 실행해 basic/menu/trl00 원본 및 021의 검사값과 해제 본문이 모두 일치함을 확인했다. 게임 진입·시스템 호출·게임 실행을 한 검사가 아니므로 runtime PASS로 옮기지 않는다. 원본 그대로 재패킹과 편집 basic 재패킹도 예상 파일과 바이트 단위로 일치한다.

로컬 `work/boot_failure_020_2026-10-03`에 원인 조사, 함수 해석, 466개 검증 영수증, 격리 함수 대조와 빌드 로그를 보관한다. `work/next_plus_graphics_2026-10-02/final_iso_readback_021.json`은 실제 021 ISO의 466멤버·643면, 보호 영역, 텍스트·폰트를 확인한 기록이다. 원본 자산과 전사·ISO는 공개하지 않는다.

사용자 실행 확인을 반영해 021을 [개발 릴리스](RELEASE_2026-10-03_021.md)로 공개했다. 새 로딩 문제가 보고되면 원본/출력 해시·기기·재현 장면을 확인해 별도로 조사한다. 종료된 CMD 검증을 다시 열거나 실행하지 않는다. 추가 이미지 번역과 실제 NEXT PLUS 상태별 리소스 범위 조사는 후속 작업으로 남긴다.
