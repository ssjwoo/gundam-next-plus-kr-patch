# 기술 연구 노트

초기 조사에서 확인한 구조와 재발 방지 조건을 정리했습니다. 초기 후보의 행 수·실행 기록·해결 전 가설은 [통합 변경 이력](HISTORY.md)으로 분리했습니다. 현재 빌드·검수 판정은 [진행 현황](../PROGRESS.md)과 [인계](../99_HANDOFF/CURRENT.md)를 따릅니다.

## 텍스트·인코딩

원문은 CP932, 한글은 전용 2바이트 인코딩을 사용합니다. 일반 ASCII는 1바이트로 유지하며 숫자를 한글 수사로 바꾸는 초기 우회는 폐기했습니다. 원문·폰트·디코더의 코드 공간을 함께 확인해야 합니다.

```text
lead  = 0x80 + ((codepoint - 0xAC00) >> 7)
trail = 0x80 + ((codepoint - 0xAC00) & 0x7F)
```

예약·이동 인덱스와 CP932 기호 예외는 `tools/make_hangul_poc.py`를 기준으로 합니다. 원문의 2바이트 인덱스는 `(b0 - 0x80) * 128 + (b1 - 0x80)`로 같은 코드 공간을 사용하므로 충돌 검사를 생략하지 않습니다. 고정 슬롯 용량을 초과하면 쓰기를 거부하며 기존 포인터 대상을 보존합니다.

| 인덱스 | 용도 |
|---|---|
| 8226 | 런타임 `%t` 상표 기호 치환 |
| 207~216 | 십진수 테이블 0~9 |
| 12000 | 예약 인덱스와 겹친 `찢`의 이동 위치 |

문자열 소비자는 여러 경로를 씁니다. 초기 디코더 `0x089BC550`와 원본 계열 함수 `0x089BC598`, 문자 폭·캐시 경로 `0x089BC5EC`를 구분했습니다. HUD의 숫자 표시와 이미지 메뉴만으로 메시지 폰트의 정상 출력을 판정하지 않습니다.

ASCII 미표시 초기 조사에서는 반환 코드만 바꾸는 실험과 글리프 요청 추적을 수행했습니다. 이후 자유 폰트·문자맵·런타임 인덱스를 적용했으므로 당시의 “한글만 그려진다”는 중간 가설을 현재 미해결 판정으로 재사용하지 않습니다. 상세 추적은 [통합 전 연구 기록](https://github.com/ssjwoo/gundam-next-plus-kr-patch/blob/78269664824c0ad91e71d5f59f6c3f209f53202c/docs/RESEARCH_NOTES.md)에 있습니다.

## 미션 레코드·숫자 테이블

원본 복호화 ELF SHA-256은 `ce917a0f7289ccce3a0db8f0783529f93ff31789c0ee0bb1842ce632f0dd0c06`입니다. 파일 오프셋 `0x0028ED18`부터 274개 미션을 포인터 체인으로 확인했으며 `0x00297490`부터 구조가 바뀝니다.

레코드는 CP932 문자열·NUL·4바이트 정렬·44바이트 메타데이터·문자열 시작 주소를 가리키는 리틀엔디언 32비트 포인터 순서입니다. 기존 문자열 인벤토리와 시작점 208개가 일치했고 66개는 새로 발견했습니다. 따라서 인벤토리의 미해결 행 수와 미션 수를 단순 합산하지 않습니다. 현재 274개 메타데이터·포인터는 원판과 일치하며 미션 텍스트는 한글로 삽입돼 있습니다.

`0x28D3B4`와 `0x2C2A24`의 숫자 테이블은 CP932 전각 숫자로 **2바이트/글자**입니다. 게임이 숫자마다 2바이트를 복사하므로 ASCII 1바이트 배열로 번역하면 조건 숫자가 깨집니다. 원본 바이트를 유지하고 폰트의 해당 숫자 코드에 글리프를 연결합니다.

스캐너가 문자열처럼 읽은 데이터·문장 중간·검증 표를 자동 번역하지 않습니다. 038에서 복원한 수치·포인터·PNG와 전체 대사 경계 근거는 [현재 결함 기록](MISSION_FREEZE_027_2026-10-05.md)에 있습니다.

## 폰트·문자 분류표

폰트는 NanumGothic·Noto Sans JP의 OFL 기반 PGF를 사용하며 ISO의 `/PSP_GAME/SYSDIR/UPDATE/DATA.BIN`에서 읽습니다. 소니 원본 폰트는 공개하지 않습니다. 폰트 생성과 헤더 검사는 `make_pgf_from_ttf.py`, 기존 레코드 보존은 `extend_pgf_glyphs.py`에서 수행합니다.

- PGF 헤더 +32·+33·+372는 정렬 단위이며 0이면 안 됩니다. 초기 LIBFONT 분석에서 0으로 나누기 트랩을 확인했습니다.
- 매핑하지 않은 문자맵 칸은 `(1 << bpe) - 1` 센티넬로 채웁니다. 0으로 두면 글리프 0번이 표시됩니다.
- PGF 니블 RLE는 `1..7`이 `(값+1)`회 반복, `8..15`가 `(16-값)`개 리터럴입니다. 초기 구현은 ttf2pgf와 405개 사례의 바이트가 같았습니다.
- 초기 시험은 139KB·165KB 폰트 표시 성공, 235KB 표시 실패였습니다. 이를 모든 환경의 정확한 크기 상한으로 단정하지 않습니다.
- 메뉴 항목은 이미지일 수 있습니다. 실제 문자열 패널·자동저장 안내 등에서 폰트를 검수해야 합니다.

폰트 경로를 `.data`의 첫 0 구간에 넣던 방식은 폐기했습니다. `0x08A01FFD`는 빈 공간이 아니라 원본 문자 분류표 `0x08A01F7C`의 일부였으며, 경로가 38개 항목을 덮었습니다. 022 이후 원본 257바이트를 보호하고 폰트 초기화 블록에 경로와 분기를 둡니다. `repair_font_path_ctype.py`와 현재 빌더의 명시적 경로를 사용합니다.

## PZZ·GIM·ISO

원본 PZZ 2,125개를 구조 파싱했고 GIM은 Index4 680면·Index8 3,592면, 합계 4,272면입니다. 이 수는 표시 텍스트 이미지 수나 모드별 한글화 분모가 아닙니다. 실제 모드 호출·메시·텍스처 선택자·UV와 함께 검토합니다.

PZZ는 XOR·zlib·고정 블록 할당 구조입니다. 교체는 원본 할당 초과를 거부하고 미변경 페이로드 해시를 검사합니다. GIM은 크기·팔레트·스위즐과 보호 픽셀을 유지합니다. 정점 형식 `0x11a`는 RGBA4444를 포함하는 12바이트 형식으로 해독했습니다. [PSPSDK 정의](https://github.com/pspdev/pspsdk/blob/master/src/gu/pspgu.h).

PZZ의 마지막 16바이트는 일반 MD5·CRC가 아닌 게임 자체 검사값입니다. 본문 32비트 워드를 64비트 누적합에 더하고 각 누적합을 다른 64비트 값에 XOR합니다. 합의 초기값은 `((본문 바이트 수 * 7) & 0xffffffff) >> 1`, XOR 초기값은 모든 비트가 1입니다. 본문 길이로 정한 XOR 키와 끝 검사값을 구분합니다. `tools/pzz_integrity.py`·패커·ISO 빌더가 입력과 출력 값을 검사합니다.

이미지 마스크 밖 변화가 없어도 글자에 가렸던 배경을 복원한 마스크 내부까지 원본 동일이라는 뜻은 아닙니다. 모드별로 공유하는 글자 조각과 동적 UV는 별도 확인합니다. 건담 타이틀 로고는 [원본 유지 정책](GUNDAM_TITLE_LOGO_POLICY.md)을 적용합니다.

ISO 크기·파일 배치·AFS 멤버 할당을 유지하고 허용한 구간만 변경합니다. 초기 텍스트 전용 빌드의 “EBOOT만 변경” 기록은 폰트·그래픽이 내장된 최신 ISO의 변경 범위를 뜻하지 않습니다.

## 주소·자료 읽기

이 원본 ELF의 조사에 사용한 파일 오프셋 변환은 텍스트 `0x3C54 + (VA - 0x08804000)`, 데이터 `0x201AF8 + (VA - 0x08A01EA4)`입니다. 다른 ELF에 무조건 적용하지 않고 로드 세그먼트를 확인합니다.

초기 PPSSPP 디버거의 `cpu.evaluate` 메모리 주소는 16진 표기로 읽었습니다. Windows GUI 빌드 로그는 stdout 대신 `--log` 경로를 사용했습니다. 이는 과거 조사 방법이며 현재 사용자의 게임 실행·CMD 검증 종료 지시를 대체하지 않습니다.

현재 열린 작업은 공유·동적 소비 경로, 아직 검토하지 않은 이미지 계열과 원문 연결이 불명확한 후보 분류입니다. 과거의 7,283행·미해결 수치를 현재 게임의 미번역 문장 수로 쓰지 않습니다. [개발 안내](DEVELOPMENT.md), [현재 집계](../reports/status.json).
