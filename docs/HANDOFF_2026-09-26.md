# 이어받기 — NEXT PLUS 한국어 패치 (2026-09-26 마감)

## 한 줄 요약

자유 폰트(OFL)로 구운 PGF가 게임의 실기 libfont를 통과하게 됐고, 검토된 기계번역
4,271행이 게임에 들어갔다. 남은 큰 덩어리는 **PZZ 데이터 파일의 텍스트**와 **실기 검증**이다.

## 이번 세션에 고친 것

1. **글리프 없는 문자 자리에 `!`가 찍히던 문제** — 문자맵에서 매핑하지 않은 칸을 0으로
   남겨뒀고 글리프 0번이 `!`였습니다. 진짜 폰트(`kr0.pgf`)처럼 센티넬 `0x3FFF`로 채우고
   글리프 0번을 공백으로 바꿨습니다.
2. **`%t` 토큰이 `찢`으로 나오던 문제** — `%t`가 실행 중에 치환되는 자리가 인덱스 8226이고
   `찢`(U+CC22)의 자연 인덱스도 8226이라 충돌했습니다. 8226을 런타임 전용으로 예약하고
   `찢`을 12000으로 옮겼습니다(`RUNTIME_INDEX_GLYPHS` / `DISPLACED_HANGUL`).
3. **미션 조건 숫자가 터무니없이 크게 나오던 문제** — 파일 오프셋 `0x28D3B4`의 십진수
   테이블(`０１２３４５６７８９`)은 **한 글자당 2바이트**인데, 이전 파이프라인이 ASCII
   1바이트로 번역해 버렸습니다. 게임이 숫자 하나마다 2바이트를 복사하니 값 10이 `2301`,
   3이 `67`로 찍혔습니다. 테이블 바이트를 원본으로 되돌리고 그 바이트가 디코더를 거쳐
   가리키는 코드(`0x1cf`~`0x1d8`)에 숫자 글리프를 넣었습니다.
4. **용어** — `악마 건담` → `데빌 건담` (워크북 2행, `デビルガンダム` = `데빌 건담`과 통일).
5. **외부 검토본 병합** — `draft` 2,125행 전부 적용(문제 0), 보류 576행은 사유와 함께 보존.
6. **슬롯 초과 179행** — 미션 패키지가 이미 가진 번역 79행을 `legacy_eboot_id`로 재사용하고,
   100행은 작품 맥락을 보고 다시 썼습니다(`프로스트 형제`, `별 부스러기`, `가능성 짐승` …).
7. **글리프 RLE 구현** — 전에는 리터럴만 써서 폰트가 2배 가까이 컸습니다. `ttf2pgf`와
   **405/405 케이스 바이트 동일**한 니블 RLE를 넣어 한글 폰트가 139,696 → 100,988바이트가 됐습니다.
8. **폰트 크기 한계 재측정** — "160KB" 메모는 방향은 맞지만 부정확했습니다.
   139KB ✅ / 165KB ✅ / 235KB ❌(열리지만 아무것도 안 그려짐).

## 다음 세션에서 할 일 (순서대로)

1. **실기 PSP 검증.** PPSSPP는 게임의 진짜 `LIBFONT.PRX`를 돌리지만 실기 커널의 폰트
   캐시·로케일 차이는 남아 있습니다. 미션 조건 숫자가 `３기`, `１０기`처럼 작게 나오는지,
   자동저장 안내문이 `메모리 스틱 듀오™`로 나오는지 확인하십시오.
2. **PZZ 데이터 파일의 텍스트.** `MS 편집` 화면 스킬 설명이 `아머치가 절충형 반격무기가…`
   처럼 읽히지 않는 한글로 나옵니다. 이 문자열은 워크북에도 EBOOT에도 없고 PZZ 압축
   데이터 파일 쪽입니다. 한글 인덱스와 원문 인덱스가 겹쳐서 생기는 문제라, 완전 해결은
   **한글을 원문이 쓰지 않는 인덱스로 재배정**하는 것입니다(인코더 `encode_hangul` +
   폰트를 함께 고치고 텍스트를 재빌드). 효과는 깨진 한글이 빈칸이 되는 것뿐이고
   원문 일본어로 되살리는 것은 불가능합니다(원문은 CP932가 아니라 인덱스 쌍).
3. **남은 행.** `todo` 2,958행은 바이트 잡음이라 실제 문자열이 아닙니다. 슬롯 초과 41행과
   코덱 거부 12행은 남아 있으니, 필요하면 ASCII로 채워 넣으십시오.
4. **이미지 글자.** 메뉴 라벨과 기체 이름 상당수는 폰트가 아니라 GIM 이미지입니다
   (`render_pzz_gims.py` 등 기존 도구 사용).
5. **릴리스 자산.** ISO와 xdelta는 게임 데이터를 담고 있어 저장소에 커밋하지 않고
   GitHub Releases에 올립니다(웹 UI 필요, `gh` CLI 없음).

## 재현 절차

로컬 작업 폴더는 `gundam/kr_patch_work`, 공개 저장소는 `gundam-next-plus-kr-patch`입니다.
두 폴더는 별개이고, 저장소에는 **코드·문서·한글 초안만** 들어갑니다.

```bash
# 1) 워크북에 검토 결과 병합
python tools/merge_mt_review.py \
  --workbook work/text/<이전>.csv \
  --input work/mt_review_handoff/<패키지>/all.input.jsonl \
  --response work/mt_review_handoff/<패키지>/all.response.jsonl \
  --output work/text/<새>.csv --report analysis/<새>_merge.json

# 2) 원문 바이트를 가진 베이스 ELF에 슬롯 쓰기 (반드시 v10_base에서)
python tools/apply_workbook_slots.py build/next_plus_development_v10_base_2026-09-26.elf \
  work/text/<새>.csv --output-elf build/<새>_base.elf \
  --restore-source analysis/original_decrypted_eboot.elf --report analysis/<새>_base_build.json

# 3) 글리프 집합과 원문 인덱스 맵 재생성
python tools/collect_glyph_set.py --workbook work/text/<새>.csv --output work/font_glyph_set_<새>.txt
python tools/collect_jp_index_map.py --workbook work/text/<새>.csv --output work/font_jp_index_map_<새>.json

# 4) 폰트 굽기 (한글 + 원문 글리프 + 런타임 글리프)
python tools/make_pgf_from_ttf.py --font tools/NanumGothic-Regular.ttf \
  --chars work/font_glyph_set_<새>.txt --size 17 \
  --metrics-from tools/ppsspp-dev/assets/flash0/font/kr0.pgf \
  --jp-font tools/NotoSansJP.ttf --jp-index-map work/font_jp_index_map_<새>.json \
  --output build/kr_font_<새>.pgf

# 5) ISO 굽기 (폰트 내장 + disc0 경로 + 디코더 베이스 패치)
python tools/build_userfont_iso.py \
  --source-elf build/<새>_base.elf --font build/kr_font_<새>.pgf \
  --embed-font-slot /PSP_GAME/SYSDIR/UPDATE/DATA.BIN \
  --source-iso ../../original_jp.iso \
  --output-elf build/<새>.elf --output-iso build/<새>.iso

# 6) xdelta (-S none 으로 만들어 아무 빌드나 디코딩 가능하게)
tools/xdelta3/xdelta3.exe -f -e -S none -s ../../original_jp.iso build/<새>.iso build/<새>.xdelta
```

## 함정 (다시 밟지 말 것)

- **`개발 메뉴`·메뉴 항목은 이미지입니다.** 폰트가 없어도 나오므로 폰트 검증 지표로 쓰면 안 됩니다.
  쓸 만한 지표는 자동저장 안내문, `개발 메뉴 → 튜토리얼`의 INFORMATION 패널,
  `개발 메뉴 → 갤러리`에 커서를 놓았을 때의 오른쪽 설명 패널입니다.
- **텍스트 슬롯에 번역을 덮어쓰기 전에는 원본 바이트 전제조건을 확인하십시오.**
  이미 번역이 들어간 ELF(v15_base 등)에 다시 쓰면 `source_mismatch`가 1,500건 넘게 나옵니다.
  번역 적용은 **항상 v10_base(원문 상태)에 한 번에** 하십시오.
- **숫자 테이블 두 곳(`0x28D3B4`, `0x2C2A24`)은 절대 번역하지 마십시오.** 2바이트/글자입니다.
  현재는 `not_displayed` 상태로 원본 바이트를 유지합니다.
- **폰트 헤더 바이트 32·33·372는 0이면 안 됩니다.** 실기 libfont가 그 값으로 나눕니다
  (`div` 뒤 `break 7`). 0이면 글리프가 하나도 안 그려집니다.
- **문자맵에서 매핑 안 한 칸은 `(1 << bpe) - 1`(센티넬)** 로 채웁니다. 0으로 두면 글리프 0번이 찍힙니다.
- **폰트가 열려도 글리프가 안 나올 수 있습니다.** 크기가 대략 192KB를 넘으면 그렇습니다.
  165KB 이하로 잡으십시오.
- **PPSSPP Windows GUI 빌드의 stdout은 파이프로 안 잡힙니다.** 로그는 `--log=<경로>`로 받으십시오.
- **경로에 공백과 한글이 있습니다.** 셸 인용에 주의하십시오(`새 폴더`).
- 파일 오프셋과 VA 변환: 텍스트는 `0x3C54 + (VA - 0x08804000)`,
  데이터는 `0x201AF8 + (VA - 0x08A01EA4)`.
